# MuMain launcher

A small, standard-library-only Go launcher that keeps a per-user MuMain install
up to date and then starts the game client. It is intentionally portable: the
first supported target is Windows x64, with Linux x64 and macOS arm64 builds
produced from the same source.

## How it works

1. Read `launcher.json` next to the executable. If it is missing, the launcher
   creates it with the defaults below.
2. Download and parse `update.json` (the release manifest).
3. Verify the manifest signature when `LAUNCHER_SIGNING_PUBKEY` is set.
4. Compare the manifest version/channel with `.installed.json`.
5. If there is no install, or a newer version is available and auto-update is
   enabled, download the matching `runtime` artifact, stream-verify its SHA-256,
   unpack it safely, and swap it into place atomically.
6. Run the client from the install directory and exit with its exit code.

Install layout (per user):

| Platform | Data directory |
|---|---|
| Windows | `%LOCALAPPDATA%\MuMain` |
| Linux | `$XDG_DATA_HOME/mumain` or `~/.local/share/mumain` |
| macOS | `~/Library/Application Support/MuMain` |

```
<data dir>/
  launcher.json
  .installed.json
  games/            # active install; client binary lives here
  games.old/        # only during an update
  updates/          # temporary downloads and staging
```

If the manifest cannot be fetched and no local install exists, the launcher
prints a clear error and exits with status 1. If a local install exists, it is
started instead, so a manifest outage never blocks play.

## `launcher.json`

```json
{
  "manifestUrl": "https://github.com/ffuhr91/MuMain/releases/latest/download/update.json",
  "channel": "stable",
  "autoUpdate": true
}
```

| Field | Default | Meaning |
|---|---|---|
| `manifestUrl` | fork `update.json` URL | Manifest to fetch |
| `channel` | `stable` | Requested channel; a channel change triggers an update |
| `autoUpdate` | `true` | Set to `false` to keep the installed version |

## Manifest schema (`update.json`)

```json
{
  "version": "1.2.3",
  "channel": "stable",
  "publishedAt": "2026-01-01T00:00:00Z",
  "signature": "base64-ed25519-signature-over-the-exact-manifest-bytes",
  "artifacts": [
    {
      "kind": "runtime",
      "os": "windows",
      "arch": "x64",
      "url": "https://github.com/ffuhr91/MuMain/releases/download/v1.2.3/MuMain-windows-native-x64-release-editor-off-no-data.tar.gz",
      "hash": "sha256-hex",
      "size": 123456,
      "zsync": "https://example.invalid/MuMain-windows-runtime.tar.gz.zsync"
    }
  ]
}
```

- `kind` is `runtime`, `data` or `launcher`; only `runtime` is consumed today.
- `os` is `windows`, `linux` or `macos` (`darwin` is also accepted).
- `arch` is `x64`/`amd64` or `arm64`/`aarch64`.
- `signature` and `zsync` are optional.
- `size` is in bytes. `hash` is the lowercase SHA-256 hex digest.

The same schema is generated by `tools/generate-update-manifest.mjs`.

## Signing (optional but recommended)

The launcher verifies an Ed25519 signature over the exact manifest bytes when
`LAUNCHER_SIGNING_PUBKEY` in `main.go` is non-empty. The key may be hex or
standard base64 encoded. An empty constant selects unsigned mode and logs a
warning once.

Generate a key pair with Go:

```bash
cat > /tmp/genkey.go <<'EOF'
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"encoding/base64"
	"fmt"
)

func main() {
	pub, priv, _ := ed25519.GenerateKey(rand.Reader)
	fmt.Println("private:", base64.StdEncoding.EncodeToString(priv))
	fmt.Println("public: ", base64.StdEncoding.EncodeToString(pub))
}
EOF
go run /tmp/genkey.go
```

Sign the manifest with the private key (for example in a release script):

```bash
printf '%s' "$(cat update.json)" | openssl pkeyutl -sign -rawin \
  -inkey private.pem -out manifest.sig
base64 -w0 manifest.sig
```

or with the Go snippet above. Put the base64 signature in `signature` and the
public key in `LAUNCHER_SIGNING_PUBKEY`.

> The current MVP leaves `signature` unset and the key empty. Signing is wired
> for later via `@semantic-release/exec` and a `LAUNCHER_SIGNING_KEY` secret.

## Build and run

```bash
cd launcher
go run .            # local development; creates launcher.json next to the binary
go test ./...
```

Cross-compile the shipped artifacts:

```bash
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" \
  -o MuMain-launcher-windows-x64.exe .
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build -trimpath -ldflags "-s -w" \
  -o MuMain-launcher-linux-x64 .
CGO_ENABLED=0 GOOS=darwin  GOARCH=arm64 go build -trimpath -ldflags "-s -w" \
  -o MuMain-launcher-macos-arm64 .
```

Artifact names shipped by CI:

- `MuMain-launcher-windows-x64.exe`
- `MuMain-launcher-linux-x64`
- `MuMain-launcher-macos-arm64`

## Security notes

- The SHA-256 is computed while downloading, so a corrupted or tampered archive
  is rejected before extraction.
- Archive extraction rejects absolute paths, `..` traversal, symlinks and
  hardlinks that escape the install root, and writes through symlinked parents.
- Install activation is a rename-based swap, so a failed update leaves the
  previous install intact.
